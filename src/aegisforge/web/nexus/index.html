Repositorio autorizado

Usa el mismo token de demostración de abajo. El operador elige la carpeta al iniciar el servidor con --inspect-repo. El inventario muestra metadatos. Si eliges «Leer y analizar archivo», se muestra su contenido solo en esta pestaña, sin enviarlo a Nebius ni aplicar parches.

Inspección no habilitada.

Vista local de solo lectura. No ejecuta el código ni lo envía automáticamente a Nemotron; comprueba que no incluya credenciales antes de compartirlo.

Primer caso real: únicamente scripts/build_scorecard.py y el defecto conocido de warnings. Se reutilizan Code Proposer y Diff Builder sin modelo; no se escribe ni ejecuta código.

Solo si el operador inició el servidor con --allow-nebius-proposals. Envía el código fuente visible (máximo 8,000 caracteres) y la solicitud a Nebius tras una confirmación escrita. Una primera consulta y, solo tras un Docker fallido, una segunda revisión autorizada; nunca automática. Ningún modelo aplica código ni ejecuta Docker desde esta opción.

La comprobación consulta una sola vez el catálogo de modelos con tu token de demostración; no envía código ni ejecuta el modelo, y no prueba el saldo o una futura inferencia.

Nebius desactivado.

Una segunda consulta de Nemotron será posible solo después de una prueba fallida en Docker y con autorización independiente; no hay reintentos automáticos.

Se acepta un diff completo de cualquier archivo de texto permitido en el inventario y leído previamente. Se valida su ruta, contenido y SHA-256. Para verificar otros archivos, añade una prueba pytest revisada por ti. No se envía a Nebius ni modifica el repositorio.

Escribe o pega una prueba pytest que compruebe el comportamiento del archivo seleccionado. Debe fallar con el original y pasar con el candidato. Se ejecutará en Docker sin red, solo tras tus aprobaciones de Trust. La verificación abarca esa prueba, no garantiza todos los comportamientos.


                      
Ejecución optativa: se comprobará este mismo diff en copias temporales con un test de regresión generado solo durante la ejecución. Trust pedirá aprobación para cada efecto. No se modifica el archivo original ni se utiliza Nebius. Docker no es una frontera absoluta para código hostil.
